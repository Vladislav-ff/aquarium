# NACRE — полный комплект для GitHub Pages, сборка 4.2

## Начните здесь

Это готовая согласованная Pages-сборка на основе доступного исходного `aquarium.html` (NACRE IV). Сохранены исходная 3D-сцена, кормление, прыжки, риф и вода. Итоговые файлы NACRE VI в текущем запросе не были доступны: её размножение, рост, охота и экосистемные сохранения НЕ включены в этот пакет. Он не выдаётся за восстановленную VI.

Весь комплект находится в одном архиве. `index.html` и `assets/` уже собраны. Для публикации не нужно вручную вставлять код или собирать фрагменты из переписки.

## Рекомендуемая публикация: GitHub Actions, библиотеки на самом сайте

1. Распакуйте ZIP. Загрузите его СОДЕРЖИМОЕ в корень репозитория, включая `.github/` и `.nojekyll`. Не загружайте только сам ZIP или внешнюю папку архива.
2. В Settings → Pages выберите Source: GitHub Actions.
3. Вкладка Actions → Publish GitHub Pages → Run workflow. При необходимости разрешите Actions для репозитория.
4. Дождитесь успешного завершения. В задании deploy появится адрес сайта.

Последующие изменения ветки `main` запускают публикацию автоматически. Если основная ветка называется иначе, измените `branches: [main]` в `.github/workflows/pages.yml` либо запускайте workflow вручную.

Workflow скачивает Three.js 0.169.0 и её необходимые модули, собирает сайт с локальными библиотеками, выполняет численные и статические проверки, затем реальный WebGL smoke-тест в Chromium с запретом внешних запросов. Публикация выполняется только после успешных проверок. В артефактах Actions остаётся отчёт браузерного теста. Сам workflow здесь не запускался: его успех подтверждается только результатом в вашем GitHub.

## Простой вариант: Deploy from a branch

Можно опубликовать уже собранные корневые файлы через Settings → Pages → Deploy from a branch → ваша ветка → / (root). При этом отключите workflow Publish GitHub Pages во вкладке Actions, чтобы не смешивать два способа публикации.

В готовой ZIP-сборке Three.js загружается с CDN. Реальная копия библиотеки не скачивалась в этой среде и в ZIP не включена. Чтобы заранее локализовать её самостоятельно, используйте Node.js 20+:

```sh
npm run vendor
npm run build
npm test
npm run check
```

После этого загрузите обновлённые файлы, `site-config.json` и `assets/vendor/three/` в репозиторий. Рабочий сайт больше не требует CDN для библиотек. Сеть нужна на этапе подготовки vendor.

## Локальная проверка

Из папки проекта запустите:

```sh
python -m http.server 8000
```

Откройте http://localhost:8000/. Через file:// внешние ES-модули могут блокироваться браузером; страница выводит соответствующее предупреждение.

## Структура

- `index.html`, `assets/`, `.nojekyll`, `404.html`, `manifest.webmanifest` — готовый сайт.
- `asset-manifest.json` — используемые версии/хешированные ресурсы и режим библиотек.
- `src/` — читаемые исходники и шаблон страницы.
- `scripts/build.mjs` — сборка статического сайта.
- `scripts/vendor-three.mjs` — загрузка закреплённого графа зависимостей Three.js и лицензии.
- `scripts/stage.mjs` — подготовка только публикуемых файлов в `site/`.
- `scripts/package.py` — повторная сборка, проверки и единый ZIP.
- `tests/` — исполняемые тесты и отчёты текущей проверки.
- `.github/workflows/` — проверки pull request и публикация Pages.
- `AUDIT.md`, `CHANGELOG.md` — область проверки, изменения и ограничения.
- `CHECKSUMS.sha256` — контрольные суммы файлов исходного комплекта на момент упаковки.

## Редактирование и повторная сборка

Редактируйте `src/`, а не хешированные файлы в `assets/`. Затем:

```sh
npm run build
npm test
npm run check
```

Для этих команд не требуется `npm install`: используются встроенные модули Node.js. Браузерные проверки требуют отдельной установки Playwright:

```sh
python -m pip install playwright==1.51.0
python -m playwright install chromium
python tests/browser-smoke.py
```

Режим по умолчанию проверяет оболочку и обработку недоступных внешних библиотек. Для реального 3D сначала подготовьте local vendor, затем:

```sh
npm run vendor
npm run build
npm run stage
python tests/browser-smoke.py --site site --real3d
```

Чтобы повторно получить один ZIP, выполните `python scripts/package.py`. Контрольные суммы относятся к состоянию до ваших правок и закономерно меняются после редактирования/пересборки.

## Управление и поведение

F — кормление, J — прыжок, N — свет, H — камера, пробел — пауза. Пульт содержит качество, ракурсы, течение, звук и диагностику. Для экономичного старта добавьте `?quality=low`.

Физика использует один проверяемый планировщик с частотой 60 Гц независимо от качества. Пауза сбрасывает частичный накопитель; скрытая вкладка не продолжает запрашивать кадры. При перегрузке время замедляется, а не бесконечно догоняется. Сохраняются только настройки представления; эта IV-сборка не сохраняет биологическую популяцию.

Локальные пути относительные: поддерживается сайт в корне домена и внутри `/repository-name/`. JS/CSS именуются по хешу содержимого. Сборщик не удаляет ранее опубликованные версии автоматически — их может ещё запрашивать закэшированный HTML. В первоначальном архиве оставлены только актуальные версии ресурсов. Service Worker не установлен.

## Подтверждённые проверки

В этой среде прошли 35 unit/численных/интеграционных проверок и 9 браузерных проверок оболочки. Vendor проверен на локальном искусственном графе зависимостей, включая рекурсивную загрузку, ошибки и защиту от выхода за закреплённый пакет. Эти фикстуры не содержат и не подменяют настоящую Three.js.

Полная реальная WebGL-сцена и сетевое скачивание настоящих библиотек здесь не выполнялись. Для них предусмотрен отдельный реальный тест в workflow публикации; его результат нельзя считать уже полученным. Подробности — AUDIT.md.
