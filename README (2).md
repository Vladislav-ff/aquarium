# NACRE — проверенная сборка для GitHub Pages

## Важно: какая именно версия здесь находится

Пакет подготовлен из доступного вложения `aquarium.html` (NACRE IV), версия сборки — 4.1 Pages. Это НЕ повторно проверенная NACRE VI из предыдущей переписки: её итоговые файлы не были доступны в текущем запросе.

В этой версии есть исходная 3D-сцена, стая, кормление, прыжки, вода и риф. Автономное размножение, рост, охота рыб друг на друга, экосистемные JSON-сохранения и 2D-резерв из NACRE VI здесь не реализованы. Не заменяйте ею действующий сайт VI, если хотите сохранить именно эти функции; сначала передайте его текущие файлы на аудит.

## Публикация — без сборочного сервера

1. Распакуйте архив. Загрузите СОДЕРЖИМОЕ архива в корень репозитория, а не сам ZIP и не внешнюю папку.
2. В корне должны лежать `index.html`, `.nojekyll`, `asset-manifest.json`, `manifest.webmanifest` и папка `assets`.
3. В GitHub откройте Settings → Pages → Build and deployment.
4. Source: Deploy from a branch. Branch: ваша ветка (обычно main), Folder: / (root). Сохраните.
5. Откройте адрес, который покажет GitHub Pages.

Пакет уже собран: Node.js не нужен для обычной публикации. Папки `src`, `scripts`, `tests` нужны для редактирования и повторной проверки. Указанные пути относительные — поддерживаются сайт пользователя и сайт проекта внутри /repository-name/.

Документация GitHub:
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
- https://docs.github.com/articles/creating-project-pages-manually

## Зависимости

В стандартной сборке Three.js 0.169.0 загружается с jsDelivr. Если CDN недоступен, сайт показывает понятную ошибку и повторный/экономичный запуск. В этой сборке нет 2D-fallback.

Чтобы разместить библиотеки на самом GitHub Pages и убрать CDN из рабочего сайта, при подготовке проекта выполните (Node.js 20+):

```sh
npm run vendor
npm run build
npm test
npm run check
```

Скрипт скачивает точную версию Three.js, нужные зависимости модулей и LICENSE, сохраняет их в `assets/vendor/three`, записывает контрольные суммы и включает `site-config.json`. После сборки загрузите обновлённые файлы вместе с vendor-папкой. Сеть требуется для подготовки vendor, но не для дальнейшей загрузки библиотек готовым сайтом. В данной среде сетевое скачивание vendor НЕ выполнялось и его результаты не включены в ZIP.

## Локальный запуск и проверки

```sh
python -m http.server 8000
```

Откройте http://localhost:8000/. Не запускайте Pages-сборку через file://: браузер может заблокировать внешние ES-модули.

Для редактирования используйте `src/`, затем:

```sh
npm run build
npm test
npm run check
```

Никаких `npm install` для этих трёх команд не требуется: все проверки используют встроенные модули Node.js. Удобнее Node.js 20 или 22.

## Управление

- F — кормление, затем нажмите в воде.
- J — прыжок.
- N — день / ночь.
- H — исходная камера.
- Пробел — пауза.
- Пульт — качество, ветер, звук, ракурсы и диагностика.
- `?quality=low` в адресе — экономичный запуск; остальные параметры адреса сохраняются.

Физика всегда 60 Гц и не меняется из-за качества графики. При перегрузке симуляция замедляется, а не бесконечно догоняет время. В скрытой вкладке RAF отменяется. Настройки вида сохраняются отдельно для пути проекта; состояние популяции эта версия не сохраняет.

## Кэширование

JS/CSS в `assets` именуются по хешу содержимого. Изменённый файл получает новое имя; не требуется просить посетителей вручную чистить кэш при каждом обновлении. Старые хешированные файлы сборщик автоматически не удаляет, поскольку их ещё может запрашивать закэшированный HTML. Удалять старые ресурсы можно отдельно, после завершения перехода всех страниц на новую сборку.

Service Worker не установлен: нет дополнительного слоя офлайн-кэша, который мог бы показывать устаревшую сцену. Не добавляйте `_headers` в надежде настроить заголовки GitHub Pages: пакет их не использует.

## Что проверено и что не проверено

- 27 модульных/численных проверок: вода, лучи видимости, контактная математика, буферы контактов и структурные гарантии планировщика.
- Проверка путей, хешированных файлов, импортов, DOM-идентификаторов и синтаксиса.
- 11 браузерных проверок оболочки/загрузки: корень и подкаталог проекта, отказ CDN, кнопки перезапуска, мобильная ширина, локальное предупреждение.
- Успешная загрузка оболочки проверялась с подставным модулем сцены. Полная Three.js/WebGL-сцена с реальным GPU в этой среде НЕ запускалась.
- Скрипт vendor проверен синтаксически, но его сетевой проход здесь не выполнялся.

Подробности — `AUDIT.md`, отчёты — `tests/`. Не интерпретируйте эти проверки как гарантию отсутствия любых ошибок или доказательство роста FPS.
