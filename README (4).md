# NACRE Pages — единый итоговый комплект 4.3

## Область сборки

Основа — доступный исходный `aquarium.html` NACRE IV. В комплекте сохранены его 3D-сцена, стаи, кормление, прыжки, риф и вода, а также внесены исправления и подготовлена публикация Pages. Отсутствующие итоговые файлы NACRE VI не выдаются за доступные: её автономные рост, размножение, охота и JSON-сохранения здесь НЕ включены. Фактический исходник и его SHA256 записаны в `SOURCE.json`; оригинал сохранён в `reference/`.

## Быстрый старт

1. Распакуйте архив и загрузите СОДЕРЖИМОЕ в корень репозитория, включая `.github/` и `.nojekyll`. Не загружайте один ZIP или внешнюю папку вместо содержимого.
2. В Settings → Pages выберите GitHub Actions.
3. Во вкладке Actions запустите Publish GitHub Pages → Run workflow.
4. Дождитесь успешных build и deploy. Адрес появится у задания deploy.

Дальнейшие изменения main запускают публикацию автоматически. Для другой основной ветки измените branches в `.github/workflows/pages.yml` или используйте ручной запуск.

Workflow получает закреплённую Three.js 0.169.0, собирает сайт с локальными библиотеками, проверяет контрольные суммы И полноту графа зависимостей, запускает тесты и реальный WebGL smoke-тест с запретом всех нелокальных запросов. Публикация следует только после успешного build. Этот сценарий здесь не выполнялся в GitHub: его результат необходимо смотреть в Actions, а не считать заранее подтверждённым.

## Готовый сайт без Actions

В архиве уже есть index.html и assets. Их можно опубликовать через Deploy from a branch → нужная ветка → / (root). В этом случае отключите workflow Publish GitHub Pages, чтобы не смешивать два механизма публикации.

Готовая ZIP-сборка пока использует CDN Three.js. Настоящая библиотека в этом окружении не скачивалась и не подменялась фикстурой. Для ручного same-origin размещения (Node.js 20+):

```sh
npm run vendor
npm run build
npm test
npm run check
```

После успешной подготовки загрузите обновлённый сайт, `site-config.json` и `assets/vendor/three/`. Тогда рабочему сайту CDN для библиотек не нужен; сеть нужна при подготовке vendor.

## Локальная работа

```sh
python -m http.server 8000
```

Откройте http://localhost:8000/. Pages-сборка не рассчитана на file:// из-за браузерных ограничений ES-модулей; об этом есть предупреждение на странице.

Редактируйте src/, затем выполните `npm run build`, `npm test`, `npm run check`. Для этих команд не нужен npm install: используются встроенные модули Node.js.

Браузерные тесты:

```sh
python -m pip install playwright==1.51.0
python -m playwright install chromium
python tests/browser-smoke.py
```

Режим по умолчанию проверяет оболочку и отказ внешних библиотек, а мобильный успешный bootstrap использует явный подставной модуль сцены. Это НЕ проверка 3D. Для реальной сцены:

```sh
npm run vendor
npm run build
npm run stage
python tests/browser-smoke.py --site site --real3d
```

## Содержимое

- index.html, assets/, .nojekyll, 404.html, manifest.webmanifest — готовый сайт.
- src/ — исходники и шаблон; asset-manifest.json — выбранные ресурсы и режим библиотеки.
- scripts/ — сборка, подготовка Three.js, статическая проверка, staging и упаковка.
- tests/ — исполняемые тесты и фактические отчёты.
- .github/workflows/ — проверки PR и публикация.
- reference/ и SOURCE.json — точная исходная база и её fingerprint.
- AUDIT.md, CHANGELOG.md — область и результаты доработки.
- CHECKSUMS.sha256 — контрольные суммы всех остальных файлов архива на момент упаковки.

## Повторная упаковка и контроль целостности

```sh
python scripts/package.py
python scripts/verify-archive.py ../nacre-pages-final.zip
```

Первая команда пересобирает, тестирует и создаёт один ZIP вне папки проекта. Для упаковки уже проверенного неизменённого дерева используйте --skip-checks. При одинаковых байтах входных файлов ZIP имеет одинаковые порядок записей, временные метки, права и содержимое. Это проверено двумя последовательными упаковками замороженного дерева. Полный повторный запуск тестов может изменить длительности в отчёте, следовательно и байты архива; не путайте эти два режима воспроизводимости.

CHECKSUMS помогает обнаруживать повреждения и изменения, но не является цифровой подписью или доказательством авторства.

## Поведение и ограничения

F — корм, J — прыжок, N — свет, H — камера, пробел — пауза. В пульте есть качество, ракурсы, течение, звук и диагностика. ?quality=low включает экономичный старт.

Один FixedStepper 60 Гц используется независимо от качества. При паузе и скрытии вкладки не идёт модельное время; при перегрузке ограничена работа за кадр. Камера остаётся доступна при паузе. Сохраняются настройки представления, не биологическое состояние.

Ресурсы имеют хеши содержимого, пути относительные. Поддерживаются корень домена и /repository-name/. Сборщик не удаляет ранее опубликованные хешированные версии автоматически: их может ещё запрашивать старый HTML. Service Worker не установлен. В публикуемом site/ отсутствуют src, reference, tests и служебные скрипты.

Выполнены 42 unit/численные/интеграционные проверки и 9 браузерных проверок оболочки. Полная настоящая Three.js/WebGL-сцена и сетевой vendor здесь не выполнялись. Vendor протестирован на искусственном локальном графе, включая ошибки и нарушение целостности; эти фикстуры не являются копией Three.js. Детали и границы — AUDIT.md.
